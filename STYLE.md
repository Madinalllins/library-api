# Правила проектирования Library API

1. Версия API указывается в `servers` в виде `/v1`. Она не повторяется в каждом пути.

2. URL обозначают ресурсы существительными во множественном числе: `/books`, `/readers`, `/loans`.

3. В URL используется kebab-case, а имена полей JSON и query-параметров записываются в snake_case.

4. HTTP-методы соответствуют назначению операции: GET получает данные, POST создаёт ресурс или выполняет действие, PUT полностью обновляет ресурс, DELETE удаляет ресурс.

5. Создание ресурса возвращает `201 Created` и заголовок `Location`. Успешное удаление возвращает `204 No Content`.

6. Схемы запросов отделяются от схем ответов. Серверные поля `id`, `registered_at`, `loaned_at`, `returned_at` и `available_copies` клиент не передаёт.

7. Неизвестные поля в телах запросов запрещаются через `additionalProperties: false`.

8. Все ошибки используют единую схему `ErrorResponse` с полями `code`, `message`, `request_id` и `details`.

9. Коллекции поддерживают фильтрацию, сортировку и пагинацию. Параметр `limit` имеет значение по умолчанию и максимальное значение.

10. Операции, способные создать дубликаты, используют `Idempotency-Key`. Ключ хранится 24 часа, а повторный запрос получает сохранённый ответ.
